Reference — states & permission-denied

Loading: skeleton per region, independent of the others — a slow Version History fetch shouldn’t stall Document Detail’s own fields.

Empty: a Tenant/Location or patient with zero visible Documents shows this panel’s empty state with “+ Upload” as the call to action — distinct from (rarer than) the ordinary case of a thin recent-view window.

Error: a failed list/detail fetch shows an inline retry within that region only. A failed write (Upload, Upload New Version) surfaces as a Toast/Snackbar.

Permission-denied: no role holds zero access outright — the operative gate is per-category row-level denial (ADR-492, demonstrated above). Org Admin’s read-all-no-upload grant hides (not disables) “+ Upload”/“Upload New Version”/“Retag”; the same hidden-not-disabled treatment applies to Retag for any role lacking write authority over a given Document’s current category.

Reference — Patient File → Documents tab entry point

Reached via Patient File’s Documents tab (PATIENT_FILE_TABS, wired this batch), pre-filtered to the open patient’s patient record ID. This entry mode does NOT apply the Global Nav default’s recent-touched/Location-scoping logic above — it’s already scoped to one patient’s (small) Document set and shows it unchanged, with category/role row-filtering still applying underneath exactly as it does everywhere else.
