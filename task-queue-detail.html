Reorder tabs (int-11) — a press-and-hold on any reorderable ac-tab (a role queue tab, or Patient Flow) enters Reorder Mode, temporarily expanding every reorderable tab to icon+label for direct drag reordering. Not separately drawn here — a static file can’t demonstrate a drag gesture; its accessible, keyboard-reachable counterpart, the Tab Reorder Panel (int-12), is shown open over this screen instead.

Reference — Action Center, Org Admin

Org Admin can claim and assign tasks on the Org Admin tab (Org Admin queue): Assign to me, or Assign to anyone holding that queue. It still clears those tasks on the screens they point to. On every other tab Org Admin reads only: Task Detail opens with no Assign, Complete, Delete or Notes field, except on a Task Org Admin created itself, where it has the creator’s rights in any queue. The New task button shows on every tab (on its own tab Queue starts as Org Admin). The Owner has Office Admin’s Assign and Notes on every queue, plus Acknowledge on the Org Admin tab. A user with no role that grants Action Center sees the pane frame with one line: “You don’t have access to Action Center.”

Reference — Filter tasks

Opened from the Filter button in the pane header. One group per filter dimension; each choice applies at once and lasts for the session. It narrows every queue tab and the open My Tasks sections, never Patient Flow or a queue’s Resolved view. While a filter is set, the chip under the tabs shows it and the button carries a dot.

Reference — Resolved view and the empty tab

Every queue keeps its history: system tasks that resolved (named by the module that resolved them) and user tasks that were completed (named by who completed them), grouped like the open list. Nothing is ever removed from the record; the Completed sections in My Tasks cover only your own last 7 days.

Reference — Editing a user task

Edit… in a user task’s More menu turns its fields into inputs in place: title, queue, assignee, due date, patient and related records. Creator, assignee or Office Admin. Clearing the queue (None — personal) makes it a Personal task; choosing a queue on a Personal task hands it to that queue, still assigned to you.

Reference — Delete a user task

Delete… in the More menu. System tasks have no Delete; they clear when the work is recorded.

Delete this task?

“Call X-ray sensor vendor about the intermittent Room 3 fault” and its notes will be deleted. This can’t be undone.

Reference — Personal and delegated tasks

A task with no queue: only its creator sees it, in My Tasks. No Assign control; Complete and the More menu show to the creator only. Choosing a queue in the Queue field hands it to that queue; Make personal on a queued task does the reverse, while the task is yours or unassigned.

Reference — Completed and resolved tasks

Opened from a Completed row in My Tasks or from a queue’s Resolved view. Every field is read-only and no action shows; notes can still be added. A completed user task names who completed it; a resolved system task names the module that resolved it.

Reference — Resolved upstream

A follow-up task whose linked record no longer needs work (here the claim paid). The banner offers one-click Complete; the task never completes by itself.

Reference — New task about a record

New task about this… on a record screen (Claim Workspace’s More menu shown here) opens the New Task dialog with that record as a related record, the Queue from the record type and the Patient pre-filled; the duplicate check warns if the record already has an open task. From Appointment Detail the related record is the appointment and the Queue is Front Desk. From a Patient Record only the Patient is pre-filled (drawn over Diane Okafor’s record).

Reference — Required training in My Tasks

When a required lesson passes its due date, the task is assigned to the person who hasn’t finished it, so it shows in their My Tasks and opens their own curriculum. The same task shows in the Office Admin queue for oversight, where it opens the completion rollup. Completing the lesson clears it in both places.

Reference — Deceased patient, future appointments

When a patient is marked deceased with visits still booked, Front Desk gets one task that lists each future appointment. Each has its own Cancel…, which opens the Cancel dialog pre-set to Practice and Patient deceased (no patient notice). The row opens Harold Vance’s Schedule tab; the task clears when no future visit remains.

Reference — Usage Near Limit (Org Admin)

When plan usage crosses its warning threshold, Org Admin gets a task on its own tab. Subscription & Billing is Owner-only, so the task shows the usage figure read-only and carries Acknowledge itself. The Owner sees the same warning on Subscription & Billing, where the acknowledgement appears once made.

Reference — PSG approval tasks (2026-10-15)

When PSG Support needs to change the practice’s data (for example reversing a mistaken merge), or PSG onboarding asks to set up the practice with the Owner before go-live, a task lands on the Org Admin tab. It’s decided right here on the task — the request lives in PSG’s console, so there’s no practice screen for it. Approve / Allow and Decline ask for your password first. Remediation: the Owner or an Org Admin; setup consent: the Owner only (action-center.md Workflow 20).
